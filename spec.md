# Спецификация: агент поиска работы на hh.ru

Версия v0.2 от 19.10.2026.

## 1. Назначение

Каждый день находить на hh.ru новые вакансии, подходящие пользователю, оценивать их и присылать короткую подборку в Telegram. По запросу пользователя — готовить сопроводительное письмо. Вести учёт откликов.

**Агент НЕ делает:**
- не откликается сам — отклик только после явного «да» пользователя по каждой вакансии;
- не меняет резюме и настройки аккаунта hh;
- не передаёт в GigaChat контакты пользователя (телефон, почту) — только текст резюме без контактов.

## 2. Профиль кандидата (вход для фильтра и оценки)

Хранится в `profile.md` (в репозиторий не входит — образец в `profile.example.md`): кто кандидат, его проекты, что ищет (формат, регионы, занятость, деньги), направления по приоритету и что не подходит. Правки профиля не требуют правки кода.

## 3. Поисковые запросы

Хранятся в `config.json`. Начальный набор:

- **Удалённо, вся Россия** (без опыта + 1–3 года): «нейросети», «ИИ», «искусственный интеллект», «AI», «промпт», «Claude», «AI-ассистент», «чат-бот», «автоматизация бизнес-процессов», «no-code», «разметка данных», «энергетика ИИ».
- **Регионы, любой формат:** «нейросети», «ИИ», «AI», «автоматизация бизнес-процессов», «чат-бот», «аналитик» — по Кирову (код hh 49), Санкт-Петербургу (2), Ленинградской области (145).

## 4. Звенья цепочки

Одно звено — одно действие. Выход звена — вход следующего. Всё, кроме звеньев 6 и 9, — обычный код без нейросети.
Изменение 19.10 (при реализации): жёсткий фильтр перенесён до «подробностей» — опыт, формат и регион есть уже в выдаче поиска, поэтому страницы вакансий открываются только для прошедших отсев (в разы меньше запросов к hh).

| № | Звено | Вход | Действие | Выход | Код |
|---|---|---|---|---|---|
| 1 | Сбор | `config.json` | Страницы поиска hh по каждому запросу (1 стр. × 50, сортировка по дате; «без опыта» и «1–3 года» — отдельными запросами), пауза 1,5 с; данные берутся из встроенного в страницу JSON (`HH-Lux-InitialState`) | Карточки: id, ссылка, название, компания, зарплата, регион, опыт, формат, дата, запросы | `agent/links.py: collect` |
| 2 | Новизна | карточки + `data/seen.json` | Убирает виденные раньше | Новые карточки | `novelty` |
| 3 | Жёсткий фильтр | новые карточки + `config.json` | Правила п. 5 | Прошедшие + отсеянные с кодом причины | `hard_filter` |
| 4 | Подробности | прошедшие | Страница каждой вакансии (повтор при сбое сети; повторный запуск докачивает недостающее) | + полный текст, навыки, адрес | `details` |
| 5 | Подвохи | вакансии с подробностями | Флаги по правилам п. 6 | Вакансии с флагами | — |
| 6 | Оценка (GigaChat) | вакансия + профиль (без контактов) | Оценка 1–10, «почему», направление, подвохи | JSON (п. 7) | — |
| 7 | Отбор | оценённые | Порог ≥ 6, топ-5 | Подборка дня | — |
| 8 | Доставка | подборка | Сообщение в Telegram с кнопками «Интересно» / «Не надо» | Отправленное сообщение | — |
| 9 | Письмо (GigaChat) | вакансия с «Интересно» + профиль | Сопроводительное письмо 5–8 предложений | Черновик в Telegram | — |
| 10 | Учёт | все события | Запись в таблицу | `data/tracker.csv` | — |

Запуск звеньев: `python3 -m agent.run collect novelty filter details` (или `all`); выходы — `data/runs/<дата>/01_collect.json` … `04_details.json`.

**Кнопки без постоянно работающего сервера:** нажатия «Интересно»/«Не надо» Telegram хранит до суток; агент забирает их при следующем запуске (или по команде в сессии) и тогда готовит письма. Отдельный круглосуточный сервер не нужен.

## 5. Правила жёсткого фильтра (звено 3)

Списки слов — в `config.json`. Отсеять (код причины):
- стоп-слово в названии: продажи, оператор, колл-центр, холодные звонки, риелтор, недвижимость, страхование, назначение встреч, кредит, продавец, курьер, грузчик, кассир, водитель, упаковщик, комплектовщик — `stop_title`;
- требуемый опыт «3–6 лет» / «более 6 лет» — `experience`;
- формат не удалённый и регион не Киров (49) / СПб (2) / Ленобласть (145) — `region`;
- в названии нет признака темы (ИИ, AI, нейро-, промпт, бот, автоматиз-, ассистент, аналитик данных, бизнес-аналитик и др.) — `irrelevant_title`; исключение — вакансии, найденные по точным словам «промпт», «Claude», «AI-ассистент», «no-code» (`trusted_fulltext_queries`);
- опубликована раньше 3 дней назад — `old` (важно для первого запуска; дальше приходят только новые).

Широкие запросы (ИИ, AI, нейросети, чат-бот, автоматизация, аналитик) ищутся только в названии вакансии (`title_only_queries`): по всему тексту hh находит, например, врачей, у которых в описании упомянут «ИИ».

Замер 19.10: собрано 826 → отсеяно 673 (`irrelevant_title` 313, `old` 256, `stop_title` 100, `region` 4) → 153 с подробностями. Обычный поток — около 40–55 новых подходящих вакансий в день.

## 6. Подвохи (звено 5, флаги, не отсев)

- зарплата «за услугу» или «за смену» при большой вилке (например, 150–300 тыс. за услугу без опыта);
- вилка шире ×10 («10 000 – 500 000 ₽»);
- «зарабатывайте в валюте», «доход без вложений», «обучение платное», «оплата за обучение»;
- в тексте нет обязанностей (меньше 300 знаков описания).

## 7. Формат оценки (звено 6)

```json
{
  "id": "138549581",
  "score": 8,
  "why": "Автоматизация процессов на Python с LLM; свои проекты засчитывают вместо опыта",
  "direction": "tech",          // tech | energy | creative | other
  "red_flags": ["офис/гибрид, только Киров"],
  "salary_ok": true
}
```

Если GigaChat вернул не JSON или не по схеме — один повтор; второй сбой — вакансия идёт в подборку без оценки с пометкой «не оценено».

## 8. Данные и файлы проекта

- `.env` — ключ GigaChat, токен бота, номер чата (уже есть; в git не попадает).
- `russian_trusted_root_ca.pem` — сертификат Минцифры для соединения с GigaChat (уже есть).
- `profile.md`, `config.json` — профиль и запросы (правятся без кода).
- `data/seen.json` — id уже виденных вакансий.
- `data/tracker.csv` — учёт: дата, id, ссылка, название, компания, оценка, статус (новая → интересно → письмо → отклик → приглашение / отказ), заметки.
- `data/runs/<дата>/` — выходы звеньев за день (для проверки и разбора ошибок).

## 9. Где и когда работает

- **Частота:** раз в день, 8:00 по Москве (предложение).
- **Место:**
  - вариант А — Mac (планировщик macOS): всё уже на месте, но Mac должен быть включён в 8:00;
  - вариант Б — облако (запланированная задача Claude Code): работает при выключенном Mac, но ключи придётся хранить в облачном окружении, а доступ из облака к hh и к GigaChat (серверы Сбера могут не пускать зарубежные адреса) ещё не проверен.
  - Предложение: начать с Mac (вариант А), облако проверить отдельно и перейти, если заработает.

## 10. Проверка качества

- **Звенья 1–3:** выборочная сверка 10 вакансий с тем, что видно на hh глазами.
- **Звено 4:** просмотр отсеянных за первые 3 дня — не выброшено ли хорошее.
- **Звено 6 (главное):** 20–30 вакансий оценивает пользователь (1–10), сравниваем с GigaChat; цель — расхождение не больше 2 баллов в 8 случаях из 10. При расхождениях правим инструкцию оценки.
- **Звено 9:** пользователь читает 3–5 писем и правит тон.

## 11. Порядок разработки

1. Утвердить эту спецификацию и `profile.md`.
2. Звенья 1–3 (сбор) + проверка.
3. Звенья 4–5 (фильтр) + проверка.
4. Звено 6 (оценка) + проверка качества на 20–30 вакансиях.
5. Звенья 7–8 (подборка в Telegram).
6. Звенья 9–10 (письма, учёт).
7. Расписание, пробная неделя, правки.
